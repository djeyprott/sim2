# sim2 working rules

Human history simulator: Godot 4 with C#, watch-only, Earth from 10,000 BCE, open-ended runs.
The design doc and milestone specs live in the claude.ai Project "sim2" (`design-doc.md`, `milestone-0-spec.md` to `milestone-3-spec.md`). They are the source of truth. The design doc and the current milestone's spec are mirrored at `docs/design-doc.md` and `docs/milestone-N-spec.md` (finished specs stay at `docs/milestone-1-spec.md` to `docs/milestone-3-spec.md`; milestone 4's spec is not yet written): to change one, edit the file and write it to the project from the file, so the two never differ.

## Scope rules

- Build only what the current milestone spec lists. Its feature list is frozen.
- New ideas go to the backlog in the design doc, not into the code.
- Each milestone gets an agreed spec before any code is written.

## Architecture rules

- `Sim.Core` never references Godot. The viewer only displays.
- Deterministic: same build, machine and seed give the same history. Single-threaded core. Never rely on the iteration order of `Dictionary` or `HashSet`. Use the core's own random streams, never `System.Random`, inside the core.
- One tick is one month. Systems declare an interval of 1, 3 or 12 months and a fixed update order.
- State lives in flat arrays indexed by cell id. A system adds its fields in `Register` through `WorldState.AddIntField` / `AddDoubleField`; anything not in `WorldState` is not saved or checksummed.
- Real systems are listed, in update order, only in `SystemCatalog.CreateDefault()`. Renaming a system or a field breaks old saves.
- Content (goods, technologies, biomes, crops) and tuning numbers live in `data/content/*.json`, which are built into `Sim.Core` as embedded resources and read through `ContentFiles`. JSON there may have `//` comments.
- Things that are not cells (regions, settlements, later states and figures) live in `WorldState` tables (`AddTable`, `EntityTable` with stable never-reused ids); run choices live in `WorldState` settings. Systems set starting state in `Initialize`, which runs once at construction before any load.
- People are population groups (design doc, "Population model"): rows in a `WorldState` table with traits (occupation now; language and religion later) and conditions (food now). Groups with identical traits in a cell are merged; at most 8 per cell. Never add per-cell population numbers outside the group model.
- Read another system's state only through the shared state names (for example `ClimateSystem.BiomeField`), and from the viewer only through `SimulationHost.InvokeAsync` or frame extractors.

## Grid

- `GeodesicGrid.Create(GeodesicGrid.EarthFrequency)` gives 225,002 cells about 51 km across: hexagons plus 12 pentagons. Cell ids are stable for a given frequency.
- Cell areas differ by up to about 12% from the mean. Always use `AreaKm2(cell)`, never assume equal areas.

## Earth map

- `data/earth.world` and `data/earth-rivers.bin` (river lines the viewer draws) are generated by the "Earth import" Actions job, which commits them along with `docs/earth-preview.png`. Never edit them by hand. Change `data/earth-overrides.txt`, `tools/prepare_environment.py` or the import tool, push, wait for the job, then `git pull`. The job's commit does not trigger CI, so push again afterwards to test against the new file.
- Sources: elevation from NOAA ETOPO 2022; monthly temperature and rainfall from TerraClimate 1981-2010 (public domain); lakes and rivers from Natural Earth 10m (public domain).
- Sea is every below-sea-level cell connected to the open ocean. Lakes come from Natural Earth; the Caspian is an `inlandsea` entry in the overrides file.
- `TerrainClass` (ocean, coast, lowland, hills, mountains, lake) is a fixed physical classification; use `IsLand`, `IsSea`, `IsLake`. Land and lake cells have baseline climate (12 monthly values); sea cells do not. Current climate, biomes and ice live in the world state (`ClimateSystem`): a cell's current temperature is baseline plus `climate.temperatureShift`, its rainfall baseline times `climate.rainfallFactor`. Ice is the biome "Ice".

## Workflow

- The cloud workspace has no .NET SDK. GitHub Actions (`.github/workflows/ci.yml`) is the build and test check: push, then read the run result with `gh run list` and `gh run view`. Artifact downloads are blocked from the workspace; have jobs commit outputs that need inspecting.
- Target framework is `net10.0` everywhere, including the viewer.
- CI prints test output (`--logger "console;verbosity=detailed"`); exit tests write their measurements with `ITestOutputHelper`, so read them from the log. Long exit tests are marked `[Trait("Category", "Exit")]` and run in their own workflow (`.github/workflows/exit-tests.yml`, one job per suite, 7,000 years, about 40 to 55 minutes each; read a finished job's log while the others run with `gh api repos/djeyprott/sim2/actions/jobs/<job id>/logs`), started by hand with `gh workflow run exit-tests.yml` when results need checking; CI skips them. Each suite shares one 10-seed run of the full simulation (fixtures in tests/Sim.Core.Tests/EarthRunTests.cs: real homelands, random homelands, no farming); add new measurements to `EarthRunResult` rather than starting more long runs. The 5-minute speed limit is checked by the timed headless step in `ci.yml` (5,000 years took 52 s with climate and foragers). To tune numbers faster, model the system in Python against `data/earth.world` first (gzip; header, then elevation i16, terrain u8, river u8, 12 monthly temperatures i16 in tenths, 12 monthly rainfalls i16).
- The "Statistics" job runs the headless runner (`--stats FILE.csv`) for seeds 1 to 3 with real and random homelands over 7,000 years and commits the yearly CSVs, statistics by region every 100 years (`-regions.csv`), origins, technology events and landings to `docs/stats/`; pull and read them to tune.
- The viewer uses Godot 4.6-stable with `Godot.NET.Sdk/4.6.0`; keep the two versions in step. CI compiles it with `dotnet build viewer/Viewer.csproj`.
- The "Windows build" job runs the viewer under a virtual display with `SIM2_SCREENSHOT` set, commits `docs/viewer-screenshot.png`, exports the Windows package and publishes it as the `dev` prerelease. To publish a numbered release, change `release-version.txt` (tags cannot be pushed from the cloud workspace); the job creates `v<version>` if it does not exist yet. Read that screenshot to see the viewer; extend `RunScreenshotScript` in `viewer/scripts/Main.cs` to exercise new UI.
- The viewer talks to the simulation only through `SimulationHost` (`LatestFrame`, `InvokeAsync`).
